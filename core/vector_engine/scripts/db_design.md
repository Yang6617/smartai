#### 向量数据库设计

| 字段类别          | 字段名      | 类型                    | 是否必需 |                          说明与示例                          |
| :---------------- | :---------- | :---------------------- | :------- | :----------------------------------------------------------: |
| **1. 核心向量**   | `embedding` | `List[float]` (如768维) | **必需** |           文本片段的向量化表示，由BGE-M3模型生成。           |
| **2. 原始文本**   | `document`  | `string`                | **必需** |        原始的文本片段内容，用于后续提示词组装和展示。        |
| **3. 来源元数据** | `metadata`  | `dict`                  | **必需** | 一个字典，记录该文本片段的“身份信息”和“位置信息”，详见下表。 |
| **4. 唯一标识**   | `id`        | `string`                | **必需** |    全局唯一的ID，用于更新或删除特定片段。建议具有可读性。    |

#### 元数据字典（来源元数据）

| 字段名              | 示例值                   |                             用途                             |
| :------------------ | :----------------------- | :----------------------------------------------------------: |
| `document_id`       | `"doc_001"`              | **关键字段**。关联到**后端数据库**中的文件主键。当需要获取文件详情（如真实文件名）时，用它来查询。 |
| `chunk_index`       | `5`                      | 该片段在原始文档中的顺序索引（从0开始），用于在源文件中定位。 |
| `source_type`       | `"markdown"`             | 源文件类型 (`markdown`, `text`, `image`)。对于图片，这里可记录图片文件格式。 |
| `source_info`       | `"# title1 > ## title2"` | **可选**。在文档内的位置信息，如Markdown的标题路径，便于精确定位。 |
| `knowledge_base_id` | `"team_abc"`             |       **关键字段**。用于实现数据隔离。知识库的唯一标识       |
| `uploader_id`       | `"user_123"`             |                上传者ID，用于审计和权限管理。                |
| `version`           | `1`                      |     预留字段。用于未来实现文档版本管理，当前可固定为1。      |
| `timestamp`         | `"2024-05-10T10:30:00Z"` |             片段创建时间，用于清理旧数据或排序。             |
